# OCWORLD v8 release

Approved scope: integrate latest ZEALWISH-WEB3 frontend and existing living-oc world, publish a new OCWORLD GitHub Pages site. Three-step character onboarding: name, concept, personality; preset/upload/generated concept art and pixel body; birth card, greeting and direct talk/world. Stable UUID characterId joins all records, survives renames, isolates characters, and preserves world progress. Local-first storage with explicit device-local status, portable import/export and Character Card V2 export. Memory facts and world moments are editable/deletable and recalled by chat. World simulation remains scripted unless online API is active; browser closure does not imply autonomous server simulation.

Visual thesis: ZEALWISH black/vermillion identity, quiet editorial workspace, clean ivory OC art plane. Navigation: characters, create, talk, world, memory, settings. Chinese-first responsive UI, accessible controls and reduced motion.

AI: GitHub Pages hosts static files only. Separate Vercel service handles OpenAI-compatible chat and image generation; no credentials in frontend. Existing subscription is not API billing. Verify candidate environment API access and hosting before claiming live AI. Styles express general techniques rather than copying named artists: cel anime, painterly, guofeng, chibi, watercolor, graphic ink, cyber techwear, pixel. Concept art prompts explicitly prohibit scenic background/text/watermarks and record reproducible prompt version. Presets are labelled; image failures retain user assets and explain error.

Deployment: preserve ZEALWISH-WEB3 main and gh-pages; push source branch release/ocworld-v8 into KINGKAZMAX/OCWORLD; deploy static frontend to OCWORLD gh-pages. Check subpath assets, iframe, fresh-browser onboarding, rename persistence, two-character isolation, import/export, memory recall, image failures, and phone layout. No wallet/mint requirement for creating a character.
